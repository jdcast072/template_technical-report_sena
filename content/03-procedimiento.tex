\chapter{Procedimiento}


Este apartado detalla el diseño y la ejecución paso a paso de las pruebas operativas aplicadas sobre la base de datos relacional de Import Tech S.A.s\supercite{SENA}. El procedimiento se desarrolló mediante la inyección intencional de sentencias de manipulación de datos (DML) anómalas, con el propósito de evaluar la respuesta del motor de base de datos MySQL ante la vulneración de sus restricciones y reglas de negocio \supercite{cobo2007}. La descripción de los hechos se documenta de forma objetiva según los resultados arrojados por el sistema.

\section{Pruebas de Integridad Referencial}
Para comprobar la solidez de las llaves foráneas (\colorbox{gray!20}{\textcolor{lineText}{\texttt{FOREIGN KEY}}}), se simuló la creación de un registro dependiente huérfano \supercite{taype2026}. Se intentó vincular un detalle de venta a un producto y una factura inexistentes en el sistema:

\begin{lstlisting}
-- Intento de inserción de un detalle de venta con llaves foráneas no registradas
INSERT INTO detalle_venta VALUES (11, 20, 2, 30000);
\end{lstlisting}

La ejecución de esta sentencia fue bloqueada de forma nativa por el sistema, arrojando el siguiente código de excepción, lo cual certifica que la base de datos restringe anomalías de cardinalidad \supercite{taype2026}:

\begin{lstlisting}
ERROR 1452 (23000): Cannot add or update a child row: a foreign key 
constraint fails (`import_tech`.`detalle_venta`, CONSTRAINT 
`fk_detalle_producto` FOREIGN KEY (`productos_id_producto`) 
REFERENCES `productos` (`id_producto`))
\end{lstlisting}

De igual manera, se realizó el mismo proceso desde la tabla ventas a clientes, generando el mismo error, garantizando la integridad referencial entre las llaves foráneas:

\begin{lstlisting}
    --Inserción de ventas con ID de un cliente inexistente
    INSERT INTO ventas(descuento, monto_final, fecha, cliente_id_cliente) VALUES (0.00,150000.00,'2025-09-19 11:00:00',15);
    -- Error que garantiza la integridad referencial de las FK.
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`import_tech`.`ventas`, CONSTRAINT `fk_venta_cliente` FOREIGN KEY (`cliente_id_cliente`) REFERENCES `cliente` (`id_cliente`))
\end{lstlisting}

\section{Pruebas de Integridad de Entidad}
El procedimiento para validar la integridad de las llaves primarias (\colorbox{gray!20}{\textcolor{lineText}{\texttt{PRIMARY KEY}}}) consistió en forzar la duplicidad de identificadores únicos dentro del catálogo \supercite{dominguez2021}. Se ejecutó una sentencia para registrar una categoría utilizando un identificador previamente asignado en el poblamiento de datos:

\begin{lstlisting}
-- Intento de inserción con una llave primaria duplicada
INSERT INTO categoria (id_categoria, nombre) VALUES (1, 'Teclado');
\end{lstlisting}

El sistema gestor rechazó la operación garantizando el principio de unicidad de la entidad \supercite{dominguez2021}, generando la siguiente alerta:

\begin{lstlisting}
ERROR 1062 (23000): Duplicate entry '1' for key 'categoria.PRIMARY'
\end{lstlisting}

Para pruebas de duplicidad como el \colorbox{gray!20}{\textcolor{lineText}{\texttt{NIT}}} del proveedor, se usó datos similares de los registros existentes, modificando casi todos sus valores a excepción del \colorbox{gray!20}{\textcolor{lineText}{\texttt{NIT}}}:

\begin{lstlisting}
    INSERT INTO proveedor (NIT, nombre, NIP, web, dir_ciudad, dir_barrio, dir_calle, dir_numero)  VALUES ('800111222-1', 'TechMundo', '11111999', 'www.techmundo.com', 'Bogotá', 'Chapinero', 'Calle 67', '14-22');
\end{lstlisting}
Generando el sigueiente error que garantiza la autenticidad del valor único entre atributos con el tipo de propiedad de campo \colorbox{gray!20}{\textcolor{lineText}{\texttt{UNIQUE}}}:
\begin{lstlisting}
    ERROR 1062 (23000): Duplicate entry '800111222-1' for key 'proveedor.NIT'
    -- Mismo resultado con NIP
    ERROR 1062 (23000): Duplicate entry '11111111' for key 'proveedor.NIP'
\end{lstlisting}

\section{Pruebas de Integridad de Dominio}
Para evaluar las restricciones de tipo de dato y obligatoriedad (\colorbox{gray!20}{\textcolor{lineText}{\texttt{NOT NULL}}}), se alteró el procedimiento de registro de un producto omitiendo intencionalmente su nombre, un campo definido como obligatorio en la estructuración física \supercite{suarez2010}:

\begin{lstlisting}
-- Intento de inserción omitiendo un atributo obligatorio (NULL)
INSERT INTO productos (nombre, precio, stock, categoria_id_categoria, proveedor_id_proveedor) VALUES ('pantalla OLED',1000000,15,NULL,NULL);
ERROR 1048 (23000): Column 'categoria_id_categoria' cannot be null
\end{lstlisting}

Como resultado de la prueba, el motor SQL detuvo la transacción, confirmando que el modelo físico exige la completitud de la información crítica para operar \supercite{suarez2010}:
\begin{lstlisting}
ERROR 1048 (23000): Column 'categoria_id_categoria' cannot be null
\end{lstlisting}

\section{Pruebas de Restricción de Eliminación}

Para la sección de Restricción por Eliminación, se demuestra que el motor de la base de datos protege la \textbf{integridad referencial} al impedir que se eliminen registros "padre" que tengan referencia con los registros "hijo".
\begin{lstlisting}
    DELETE FROM categoria WHERE id_categoria = 1;
\end{lstlisting}

A diferencia de la evidencia 3 donde se usaba \colorbox{gray!20}{\textcolor{lineText}{\texttt{DELETE}}} para limpiar registros temporales, en esta parte de la evidencia 4, se usa la sentencia de operación \colorbox{gray!20}{\textcolor{lineText}{\texttt{DELETE}}} para provocar un Error 1451 intencional.
\begin{lstlisting}
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`import_tech`.`productos`, CONSTRAINT `fk_producto_categoria` FOREIGN KEY (`categoria_id_categoria`) REFERENCES `categoria` (`id_categoria`))
\end{lstlisting}

En este segundo escenario, se intentó dar de baja a un registro en la tabla padre \colorbox{gray!20}{\textcolor{lineText}{\texttt{proveedor}}}, el cual actúa como el distribuidor de ciertos artículos existentes en el inventario de Import Tech S.A.S.

\begin{lstlisting}
-- Intento de eliminar un proveedor referenciado por la tabla Producto
DELETE FROM proveedor WHERE id_proveedor = 1;
\end{lstlisting}

\begin{lstlisting}
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`import_tech`.`productos`, CONSTRAINT `fk_producto_proveedor` FOREIGN KEY (`proveedor_id_proveedor`) REFERENCES `proveedor` (`id_proveedor`))
\end{lstlisting}
